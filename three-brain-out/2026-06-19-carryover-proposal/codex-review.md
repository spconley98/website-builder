**Findings**

1. **`catch-up` risks becoming a second `_HOT.md`.**  
   Proof: it would print phase, resume point, blockers, last session, gotchas, and next action: almost exactly `_HOT.md`’s job. AGENTS says current state authority is `MEMORY.md`, with `_HOT.md` as the generated digest. A separate renderer from `MEMORY.md` can drift by extraction rules, wording, or stale handling.  
   Fix: make `catch-up` an ephemeral view over existing `_HOT.md` plus live git status. If `_HOT.md` is stale, warn or run `vault hot` only when explicitly requested. Do not invent independent “suggested next” logic.

2. **Do not hand-edit `_HOT.md` to mark the blocker resolved.**  
   Proof: `_HOT.md` says “GENERATED by `leadpipe vault hot` — do not hand-edit.” The proposal says “flip the `_HOT.md`/`MEMORY.md` blocker entry,” which creates generated-file churn and can be overwritten.  
   Fix: update `MEMORY.md`, then run `uv run leadpipe vault hot`.

3. **Renaming only the project skill is not enough if docs still say `context-transfer`.**  
   Proof: the current failure happens because agents invoke the generic name and Claude resolves the global AAS skill. Any remaining “wrap up / context-transfer” instruction can still fire the wrong brain.  
   Fix: replace operational invocations with `wb-context-transfer` everywhere active: `AGENTS.md`, `.claude/skills/.../SKILL.md name`, `_HOME.md`, start/end prompt guides, onboarding docs, sync guide, `MEMORY.md`. Historical session logs can stay.

4. **The global AAS skill remains a loaded trap.**  
   Proof: `_HOT.md` says the global skill “shadows every repo.” Renaming this repo’s skill prevents only users who remember the new name from hitting it. A future generic “wrap up” may still resolve globally.  
   Fix: best fix is move/rename the global AAS skill into the AAS repo. If that is out of scope, website-builder must ban bare `context-transfer` in current protocol and document `wb-context-transfer` as the only valid invocation.

5. **New “Start-Session guide doc” is probably duplication.**  
   Proof: repo already has `docs/project/AGENT_PROMPT_GUIDE (Start Session).md`, `_HOME.md`, `SYNC_GUIDE.md`, `ONBOARDING_MATT.md`, and AGENTS §8. Another guide adds one more stale surface.  
   Fix: update the existing Start Session guide. Do not add a new guide unless replacing one.

6. **`--sync-check` contradicts “read-only + local by default” if it runs `git fetch`.**  
   Proof: `git fetch` mutates remote-tracking refs, can hang on auth/network, and turns cold-start into network I/O. AGENTS §7 requires fetch for stale-copy protocol, but not every cold start needs it.  
   Fix: split modes: default `catch-up` uses `git status --short --branch` only; `--sync-check` compares existing refs; `--fetch` explicitly runs `git fetch origin` with timeout and clear failure handling.

7. **“Top In-Progress” assumes structured task state that may not exist.**  
   Proof: `_HOT.md` has bullets, not a strict task schema. `MEMORY.md` is prose. Ranking “top” can become heuristic and wrong.  
   Fix: print the first `_HOT.md` “Active tasks” item or label it plainly as “first listed active task,” not “resume point,” unless a real structured field is added.

8. **Wrapper skill adds maintenance unless it delegates completely.**  
   Proof: `wb-catch-up` as a Claude skill can drift from CLI behavior, repeating the same class of wrapper/core mismatch that caused the current blocker.  
   Fix: wrapper must be tiny: “run `uv run leadpipe vault catch-up` and report output.” No separate parsing or policy.

**Verdict: FIX-FIRST**

Single most important change: define `catch-up` as a non-authoritative printer for `_HOT.md` plus live/local git status, not a second digest from `MEMORY.md`. Then rename the skill everywhere and regenerate `_HOT.md` from `MEMORY.md`, instead of editing it directly.
